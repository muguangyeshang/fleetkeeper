# Documentation

Everything a user or a reviewer needs is in this directory. All documents are
plain Markdown (plus one standalone HTML sample), checked into the repository
and included in the sdist. None of them need a network connection to read.

| Document | Language | Read it if |
|---|---|---|
| [说明书.md](说明书.md) | 中文 | You want to double-click the exe and be done. Covers every button, every config field, and what each status label means. |
| [USER_GUIDE.md](USER_GUIDE.md) | English | You run the CLI, edit `fleet.json`, schedule sweeps, or wire up alerts. Contains the complete configuration reference. |
| [ARCHITECTURE.md](ARCHITECTURE.md) | English | You want to review, extend, or audit the design. Module map, sweep data flow, gating rules, state machine, performance limits, test strategy. |
| [assets/status-page.html](assets/status-page.html) | HTML | You want to see the offline status page before installing anything. Download it and double-click. |

Repository-root files serve GitHub-level governance rather than usage:
[CONTRIBUTING.md](../CONTRIBUTING.md), [SECURITY.md](../SECURITY.md),
[RELEASING.md](../RELEASING.md), [CHANGELOG.md](../CHANGELOG.md),
[LICENSE](../LICENSE).

## Documentation conventions

- Commands in the guides assume the editable install (`python -m pip install -e .`).
  On a `PYTHONPATH=src` install, prefix with `PYTHONPATH=src`.
- Example ports `59201` / `59202` / `59211` / `59212` are ephemeral loopback
  ports used when the examples were captured. No example uses a real service
  name, hostname, user path, or credential from the author's machine.
- Terminal blocks in the guides are copied from real runs, not drafted by hand.
  The two-service demo fleet is one live local HTTP server plus one port with
  no listener. Records of those runs are in `_pk_docs/` at the workspace level
  and are not part of the repository.
- `assets/status-page.html` is generated by `report.render()` from a real
  `status --json` result. It has zero external references (`grep -c
  "https\?://" assets/status-page.html` returns `0`) and no JavaScript.
- Config examples use relative paths. Paths resolve against the directory of
  the config file, never the current working directory.

## Regenerating the sample page

From a checkout, with a service listening on a loopback port and another port
left dead:

```bash
PYTHONPATH=src python -m fleetkeeper.cli --config fleet.json status --json > rows.json
PYTHONPATH=src python -c "
import json, sys
from fleetkeeper import report
rows = json.load(open('rows.json', encoding='utf-8'))
data = report.normalize(rows)
sys.stdout.write(report.render(data))
" > docs/assets/status-page.html
```

The checked-in sample was produced by `_pk_docs/make_sample_html.py` in the
workspace, which starts the demo HTTP server itself. Regeneration is optional;
the committed file is a valid standalone page as-is.
